Aula 05

WebAssembly com Blazor

O WebAssembly permite rodar no navegador código compilado de outras linguagens além do JavaScript. Com o Blazor WebAssembly, a aplicação web inteira é escrita em C#, organizada em componentes .razor que misturam HTML e código.

  • WebAssembly
  • Blazor
  • C# / .NET 10
  • MudBlazor

O que está sendo visto

  • SPA em C#: o navegador baixa o runtime do .NET compilado para WebAssembly e executa a aplicação no próprio cliente, sem servidor de aplicação.
  • Componentes Razor: arquivos .razor com HTML e um bloco @code em C#; a diretiva @page define a rota de cada página.
  • Layout e navegação: MainLayout e NavMenu envolvem todas as páginas.
  • Estado e eventos: a página Counter atualiza a tela a cada clique.
  • Busca de dados: a página Weather lê um JSON com HttpClient. No projeto a_blazor, o código dela foi separado em Weather.razor.cs (code-behind) e o modelo de dados foi para a pasta Models.
  • Biblioteca de componentes: o projeto b_mudblazor refaz o template com o MudBlazor (Material Design): MudLayout, MudAppBar, MudDrawer, MudTable, MudButton e outros.

Como executar

Os projetos Blazor precisam ser compilados, então não há uma página HTML para abrir diretamente. Com o .NET SDK 10 instalado, entre na pasta de um dos projetos e rode:

cd a_blazor        # ou: cd b_mudblazor
dotnet watch

O dotnet watch compila, abre o navegador e recompila a cada arquivo salvo. Endereços configurados em Properties/launchSettings.json:

  • a_blazor: http://localhost:5164
  • b_mudblazor: http://localhost:5103

O wwwroot/index.html de cada projeto é só a "casca" da aplicação: aberto direto no navegador, ele fica em branco, porque depende dos arquivos gerados na compilação.

Estrutura de arquivos

Os dois projetos seguem a mesma organização do template blazorwasm. A estrutura de a_blazor:

  • 05_WebAssembly/
    • index.htmlesta página
    • .gitignoreignora as pastas geradas bin/ e obj/ no Git
    • a_blazor/template padrão do Blazor WebAssembly (visual com Bootstrap)
      • a_blazor.csprojarquivo do projeto: versão do .NET e pacotes NuGet
      • Program.csponto de entrada: registra o componente raiz em #app e os serviços, como o HttpClient
      • App.razorroteador: escolhe a página pela URL e aplica o layout padrão
      • _Imports.razor@using compartilhados por todos os componentes
      • Layout/
        • MainLayout.razormoldura comum a todas as páginas
        • NavMenu.razormenu lateral de navegação
        • *.razor.cssCSS isolado: vale só para o componente de mesmo nome
      • Pages/
        • Home.razorpágina inicial (/)
        • Counter.razorcontador: estado e evento de clique
        • Weather.razortabela com a previsão do tempo (marcação)
        • Weather.razor.cscódigo C# da página Weather, separado da marcação
        • NotFound.razorpágina exibida quando a rota não existe
      • Models/
        • WeatherForecast.csclasse com os dados de uma previsão (data, temperatura, resumo)
      • Properties/
        • launchSettings.jsonportas e perfis de execução local
      • wwwroot/arquivos estáticos publicados como estão
        • index.htmlpágina hospedeira, com a div#app onde o Blazor é montado
        • css/app.cssestilos globais
        • sample-data/weather.jsondados lidos pela página Weather
        • favicon.png, icon-192.pngícones da aplicação
    • b_mudblazor/o mesmo template com MudBlazor
      • b_mudblazor.csprojinclui o pacote MudBlazor
      • Program.csregistra os serviços do MudBlazor com AddMudServices()
      • Layout/MainLayout.razorlayout com MudLayout, MudAppBar e MudDrawer
      • Pages/Home, Counter, Weather (com MudTable) e NotFound, com o código em @code
      • wwwroot/página hospedeira, CSS, ícones e weather.json
